# 让 AI 按这套方式工作

先让 AI 读取根 AGENTS.md 和 README，再读链接的任务、接入、状态、操作和发布文档。
其他 AI 产品若不自动读取 AGENTS.md，在其项目规则入口链接这些文件即可，无需复制
整个私有聊天。规则不替代当前用户的明确授权和任务指定环境。

首次采用提示词：

> 读取本仓库 AGENTS.md、README 与 docs/ 中的开发/接入/状态/操作/发布指南。我要把
> 自己的项目接入这套模式。先核验真实 Git root、owner/repo、可见性、分支和脏改动，
> 读取已有规则与精确工单。仅使用我授权的 GitHub/Linear 工作区。查重并创建初始化
> Issue，加入我的总 Project，核验 native 镜像或创建唯一 linked 关联任务。保留旧规则
> 和 CI，在独立分支以 Draft PR 加入所需模板。真实配置放本地私有文件。报告实际权限
> 与验证缺口，不猜测已配置、已部署或已验收，不把示例 ID 用作真实 ID。

开始功能/修复提示词：

> 按本仓库 AGENTS.md 完成这个需求：<目标>。先读准确源 Issue 与验收条件，核验真实
> checkout 和当前证据。使用独立分支/worktree，及时维护 Issue、PR、Project、Linear，
> 所有阶段以完整 SHA 和可回读证据为准。Draft PR 属开发。不要覆盖原验收或依赖。
> 审查、合并、发布、部署、启用与真实验收按当前授权逐项判断；缺授权时先完成可审查
> 候选和交接包。所有状态更新后回读，未知和未运行分别记录。

恢复任务提示词：

> 恢复前读取原聊天/需求、源 Issue、分支/HEAD、脏改动、现有 PR 和最新回执。先对账
> 已有实现与负责人，不重复派工、实现或触发服务器任务。保留已存在的审核/发布/验收
> 阶段。先报告哪些是当前证据，哪些仅是旧快照，再继续授权范围内的下一步。

审核/发布提示词：

> 按 docs/RELEASE.md 审查当前准确 SHA，逐条核验原验收条件和证据。区分静态、指定
> CI/数据库、集成、合并、产物、部署、启用和真实用户验收。保留 FAIL/UNKNOWN/NOT_RUN。
> 只在本次授权与全部条件满足时推进相应阶段。不要自动关闭待上线/验收的源任务。

使用者还应复制 templates/AGENTS.md 到自己的仓库并填写本地规则链接，保留已有内容。
不要把私有服务器、账户、组织登记或聊天历史放进公共 AI 规则。Agent 能力不足时应
明确无法执行的步骤、需要的权限和下一步；不能用“已保存”代替外部平台回读。
