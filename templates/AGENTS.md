# 项目开发交付约定

采用本规则前，维护者填写本仓库真实流程文档、平台链接、验证环境与负责人；保留原有
AGENTS 和 CI。不要把示例平台 ID 或私有凭据放进公开规则。

工程任务先核验 Git root、owner/repo、分支、完整 HEAD、脏改动及所有适用指引。
查重后创建准确 GitHub Issue，保存范围、验收条件、依赖、验证环境与下一步。
加入本团队总 Project，维护项目、优先级、工作类型、阶段与验证层级。
按精确源 URL 查 Linear 原生镜像；已配置 native 时不另建重复项，linked 模式只建
一个带源 attachment 的任务并回读 UUID，明确同步方式。

使用独立分支/worktree，保护现有改动；建议 codex/<team>-<N>-gh-<N>-<description>。
提交引用源 Issue，默认 Draft PR。PR 含准确源链接、Linear 关联（私有时受控保存）、
完整 SHA、验收与验证、风险、回滚和剩余步骤。需部署/启用/验收的任务避免自动关闭。

开始实施、提交/推送、Draft PR、正式审核、CI、阻塞、交付或下一步变化时，即时回写
Issue、PR、Project、Linear，并逐平台回读。Draft PR 属开发，正式请求审核才待审核。
不覆盖原验收正文/依赖。精确源绑定、唯一 event_id、当前正文 SHA256、完整源码 SHA
和证据都要核验。冲突或未知停止该项写入并对账；不要盲目重复外部副作用。

本地/静态、指定 CI/数据库、集成、合并、产物、部署、启用、真实客户端验收分别记录。
FAIL/UNKNOWN/NOT_RUN/SKIP 不能记通过。叶实现不能推进父交付。跨仓工作设协调与
各仓实施 Issue，用真实链接与阻塞关系连接。全部验收满足且负责人确认后才完成源系统。

合并、正式发布、部署、启用、资金/通知按当前用户明确授权分别办理。任务追踪授权不
授予生产操作。定时对账仅补漏、不发起完成；无变化保持安静，仅通知有意义的变化。
实际配置与运行资料受控保存，不提交账号、主机、私有任务、凭据或日志。
